# Privacy pane disclosure

The text the Privacy pane shows, one entry per item in `PrivacyDisclosure.items` (`Sources/JilpaCore/Privacy/Disclosure.swift`), keyed by its id. A change that adds a sensor, a stored field, a network call or an automation read adds its item and its entry here in the same change; a test fails when a table of the activity store has no item. When the pane exists these strings move to its string catalog under the same keys and this file keeps only the list.

Everything below stays on this Mac. Excluding an app, a folder or a website hides what is already stored about it, at once and everywhere, and Erase activity removes it from the disk. While private mode is on, or an app is paused or excluded, nothing in "kept on disk" is written unless the entry says so.

## Kept on disk

| Id | Text |
| --- | --- |
| `stored.sessions` | For each Open, Save or Export dialog in an app you have not excluded: the app and its version, the macOS build, whether it was an open or a save, sheet or window, when it opened and closed, the folder it started in, whether you confirmed or cancelled (or that Jilpa could not tell), the folder you confirmed in, the file's extension, the context that was active, and whether Jilpa changed the folder by itself and why. **Never the file's name.** For a browser download, the website's host name (`example.com`, never the page address), or a note that it could not be determined. |
| `stored.folders` | Each folder named above: its path, the volume and file identifiers that let Jilpa recognize it after a rename, whether it is a Git repository's root, and whether it was reachable when last checked. With it, the volume and file identifiers of each folder above it (identifiers, not their paths), which is what lets a folder exclusion you add later also hide everything inside that folder. |
| `stored.configuredFolders` | For a folder you chose yourself (a favorite, a default, a rule's destination): the same identifiers and a bookmark, so that Jilpa can offer to repair the entry if the folder is renamed or moved. This is your configuration, not activity: it is kept in private mode and survives Erase activity, and it goes when you remove the entry. It is never kept for a folder you have excluded. |
| `stored.counters` | How often, and how recently, you confirmed a dialog in each folder, counted separately per app, open or save, kind of file, context and source website. This is what suggestions are ranked from. |
| `stored.suggestionLog` | The up to five folders Jilpa would have suggested when a dialog opened, with their scores and the kinds of reason behind each (never the counts), and, once you confirmed, the place your folder had in that list or that it was not in it. This is how its accuracy is measured on this Mac before it is ever allowed to navigate by itself. A list that names a folder you have excluded is not kept at all. |
| `stored.navigations` | Each folder change Jilpa made: the app whose dialog it was, what triggered it, the method, the target folder, the result and the reason, how long it took, whether you corrected it afterwards, and whether the move left anything behind it should not have (input sent, a name, selection or focus not restored, a sheet left open, or that Jilpa could not tell). A dialog's attempts are kept whether or not it was ever confirmed. |
| `stored.consent` | Per app, whether you allowed predicted navigation, and whether Jilpa has suspended it and why. |
| `stored.saveOutcomes` | For a confirmed save, if you have turned on save history: whether the file was seen to be written, where, its file identifiers and **its name**. This is the only place a file name is kept. |

## Kept in memory only

| Id | Text |
| --- | --- |
| `memory.log` | The last 2,000 lines of Jilpa's own log. Paths, file names, window titles, addresses and the names you give rules and favorites are reduced to their shape before a line is made (`<path home/Documents +2>`, `<name 14 chars, .pdf>`), and an app you excluded or paused is written as `<app>`. The lines leave memory only if you ask for a diagnostics bundle, which you read before deciding to send it. |
| `memory.timings` | How long Jilpa's own steps took (attaching its panel, ranking, navigating, searching), as numbers per kind of step. |

## Read from other apps and the system

| Id | Text |
| --- | --- |
| `sensed.apps` | Which apps are running: for each, its bundle identifier, and its version if it is installed in an Applications, System or Library folder (an app anywhere else is never opened to find out). For each app you have not paused or excluded, Jilpa asks macOS to tell it when that app opens a window or a sheet or moves to another window, and reads such a window's kind and identifier to tell whether it is an Open or Save dialog. **Never a window's title.** None of this is written down by itself; what is kept about a dialog is listed under "kept on disk". Private mode does not change it, because this is how Jilpa finds a dialog to draw its panel beside. Pausing or excluding an app ends it for that app at once. |

| `sensed.dialog` | From an Open or Save dialog Jilpa has recognized, in an app you have not paused or excluded: the folder it shows, which Jilpa works out from the file addresses of the items the dialog lists (the first listed item, and the selected ones, at most sixteen); how many items are selected; the file name the dialog proposes and which part of it is selected; the short folder name in the dialog's path menu, which Jilpa never opens; where the keyboard is (in the name field, in the listing or elsewhere, as a kind of control, never what it contains); which view the listing is in; and whether the dialog's own Open or Save button can be pressed. When one item is selected in column view Jilpa also asks the disk whether it is a folder, a file or a package. When the folder the dialog shows changes, Jilpa asks the disk for the identity of the folder before and the folder after — the numbers the system gives a volume and an item, so that two names for one folder are not taken for a move. It does not open the item or list the folder. **Never the dialog's title, and nothing of the files themselves.** Jilpa asks macOS to tell it when the dialog's path menu, its file name field or its listing changes, so that all of this is read again whenever the dialog changes; it is held only while the dialog is open. None of it is written down by itself, and the file name is never written at all, except as "kept on disk" says for save history. Private mode does not change the reading, because the panel beside the dialog is drawn from it. |

| `sensed.saveOutcome` | For a Save or Export dialog in an app you have not paused or excluded, and only while that dialog is open: Jilpa asks macOS to tell it when anything changes in the one folder the dialog is showing, so that it can tell whether your file was written. It looks only at names that could be the file the dialog proposes — the same name, the same name with another extension, and the half-finished names a download leaves behind — and asks the disk for those names alone: whether each exists, how large it is, when it was made and last changed, and the numbers the system gives a volume and an item. **Any other name in that folder is dropped the moment it arrives, and never looked up.** Jilpa does not list the folder and does not open any file. The watch ends with the dialog, at the latest a few seconds after it closes, and it moves with the dialog if you navigate elsewhere. None of this is written down unless you have turned on save history, and then only as "kept on disk" says. In private mode, and for an app you have paused or excluded, there is no watch at all. |

| `sensed.documentWindow` | Many apps answer an Open or a Save by showing the file in a window of their own, and that is the only sign Jilpa has that an Open dialog was confirmed at all. So while a dialog of an app you have not paused or excluded still has an outcome to decide — while it is open, and for a few seconds after it closes — Jilpa asks macOS to tell it when that same app opens a window, and asks such a window for the one file it is showing. It compares that file with what the dialog had selected and with the folder the dialog was last showing, by asking the disk for the numbers the system gives a volume and an item. Jilpa asks **only that app**, **only about the one file the window is showing**, and **never the window's title or anything inside it**; a window of any other app is never asked. The answer is used to decide confirmed or unknown and is not written down; what is kept is listed under "kept on disk". In private mode, and for an app you have paused or excluded, Jilpa does not ask at all. |

## Owed when they land

Sensors (the browser source, the developer context from terminal apps, the clipboard suggestion), network calls (updates, compatibility data) and the automation surface have no product code yet. Each adds its item and entry with the change that adds it.
