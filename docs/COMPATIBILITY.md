# Compatibility matrix

v0 · 2026-09-20 · generated from the spike 2 soak on one Mac · nothing here is advertised to users yet

This is the list of app and dialog variants Jilpa has been measured against, with the counts behind each label. The PRD requires it (App compatibility, and the D3 sample rule); the measured cells are regenerated from raw soak data by `Scripts/make-compatibility.sh` and the rest is written by hand from the spike write-ups. **No cell is advertised without counts.** A cell that is not listed is unmeasured, and the product treats an unmeasured dialog as unknown: it stays as usable as it is without Jilpa.

v0 has one host that was navigated: FixtureApp, which presents real `NSOpenPanel` and `NSSavePanel` dialogs drawn by the system's open-and-save service. It says the navigation strategy is safe and reliable against the system panel on this macOS build. It does not say any third-party app is supported. Real apps enter the navigation table when a per-app soak driver exists for them (WP4) and the owner has agreed to their being driven.

## Levels

| Level | Meaning | What the product does |
| --- | --- | --- |
| supported | The 95% upper confidence bound on the cell's failure rate is at or below 0.5%, with no contract violation observed. That is 598 clean attempts with no failure, 947 with one, 1,258 with two, 1,549 with three (exact one-sided Clopper-Pearson) | Full panel; automation under the consent contract |
| provisional | Measured, no contract violation, but fewer attempts than the bound needs. The counts are shown | Labelled panel, manual navigation only |
| degraded | Recognised, and one named capability cannot be offered in that state. Jilpa refuses that capability with a reason and the rest works | Panel with the missing capability explained |
| unsupported | Excluded, unrecognised, or a contract violation was observed in the cell. One violation makes a cell unsupported whatever the counts, until the cause is fixed and the cell is measured again from zero | Nothing is drawn and nothing is sent |

A failure in these tables is any attempt the safety oracle did not pass as clean. "Not clean, no violation" counts attempts that did not end as they should have and broke nothing: Jilpa stopped sending input because the host lost frontmost status mid-attempt, or it could not verify the arrival and said so. They cost the cell attempts but break no contract. A cell in which no attempt was clean and none broke a contract is degraded: the capability is refused in that state, and more attempts would not change the label. A violation is a broken navigation safety contract: a confirmed dialog, a changed filename, a new file, or a key event that reached another app.

## Navigation cells

Strategy for every row: Go to Folder by `Command+Shift+G` posted to the open-and-save service's pid, the path set by AX value on the sheet's field, the suggestion row checked against the target, `Shift+Return` to accept, arrival verified by volume and file identifier. See [spikes/S2-navigation-soak.md](spikes/S2-navigation-soak.md).

## Dialog states that are refused by design

These hold for every host measured so far. They are states of the system panel, not of an app.

| State | Level | What happens | Evidence |
| --- | --- | --- | --- |
| Save panel collapsed (the compact form with no file browser) | degraded | Navigation is refused before any input with the reason `no-service`: all of the collapsed panel's elements belong to the host, there is no folder source to verify an arrival with, and Jilpa does not expand the panel for the user. Once the user expands it, the panel is an ordinary save panel | S2 surprise 7, S3a |
| Target folder is empty, panel in list or icon view | degraded | The panel does arrive, but no item exists to read the folder from, so the arrival cannot be verified and the attempt is reported as failed, not as done. Column view names the empty folder and is unaffected | S2 surprise 10, S3a; counts in the `empty` rows above |
| Target missing, not a folder, on an unmounted volume or online-only | refused | No input is sent; the reason is shown (contract 5). This is the contract working, not a compatibility gap | S2 fault case `missing-target`, 30 of 30 refused |

Spike 1 recognised and classified the dialogs of these apps without navigating them. The driver pressed menu items and Cancel only. They are **unmeasured for navigation** and have no level yet.

| Preview | 11.0 | yes | 5 | 5 | 0 | Same launch-time Open panel |
| Script Editor | 2.11 | no | 4 | 4 | 0 | |
| Terminal | 2.15 | no | 2 | 2 | 0 | Its Open panel is a modal `AXDialog`, not a standard window |

Across those and 16 bystander apps, 98 file dialogs matched the signature and 0 of 55 other windows did. Export is recognised as Save and a folder chooser as Open unless per-app signature data says otherwise; all 15 Export dialogs and all 10 folder choosers were classified that way. See [spikes/S1-detect-classify.md](spikes/S1-detect-classify.md).

## Unmeasured

Nothing is known about these, in either direction. Office, Adobe, Java and Qt apps were not installed on the test Mac; the Electron and Catalyst apps that were running (Proton Pass, WhatsApp) were bystanders whose file dialogs were never opened.

- Microsoft Office, Adobe apps, Electron apps' own file dialogs, Catalyst apps' file dialogs, Java and Qt apps
- Any panel with a custom accessory view, any app that draws its own file browser
- macOS 27 (the PRD asks for 27 first, then 26; no 27 system was available). Intel Macs are out of scope
- Network volumes, File Provider (cloud) destinations and external disks as navigation targets; spike 8 measures how such destinations are identified, not how a panel reaches them
- More than one display, Stage Manager, full-screen hosts

## How a cell is added or re-qualified

1. Write or extend a soak driver for the host. A driver opens a dialog, runs attempts and always cancels; the oracle, not the driver, decides pass or fail.
2. Run about 600 attempts per cell (`jilpa-soak run … --out <data-dir>/main-<cell>.jsonl`). After any failure, keep going until the bound is back under 0.5% or the cause is understood.
3. `Scripts/make-compatibility.sh` regenerates the table. Raw data stays out of git.
4. Every advertised cell is re-qualified each release, and a new macOS developer beta gets a matrix run within one week.
